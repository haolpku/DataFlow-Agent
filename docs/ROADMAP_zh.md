# DataFlow-Agent 路线图 / TODO

> 目标:把本项目做成**组内乃至更广泛使用的 agentic 轨迹数据合成框架**——任何人都能几行代码接入自己的环境、跑出高质量可训练数据。
>
> 本文是活文档。认领任务请在条目后标注 `@你的名字`;完成后打勾并注明 PR / commit。

图例:🔴 高优先 · 🟡 中 · 🟢 低/长期 · ✅ 已完成

---

## 0. 现状快照(已完成 ✅)

- **六个算子**:`AgentExploreGenerator`(线性)、`AgentExploreTreeGenerator`(分支树)、`TrajectoryQualityEvaluator`(LLM 打分)、`TrajectoryFilter`(规则过滤)、`TrajectorySelector`(top-N 多样选择)、`TrajectoryRefiner`(修复,已并发化)。
- **三个沙箱后端**:`MockSandboxClient`(离线)、`HTTPSandboxClient`(远程 HTTP)、`CodingSandboxClient`(真实工作区 + pytest)。
- **规模化**:`sharded_run`(分片 + 断点续跑)、算子级线程池并发。
- **质量保障**:46 个离线测试;真实 API 端到端验证过 coding / 知识检索 / 探索树。
- **文档**:`DESIGN_zh.md`(设计理念)、`CAPABILITIES_zh.md`(能力清单)。

## 1. 🔴 让"别人能用起来"(采纳门槛)—— 最高优先

这是框架能否被组内推广的关键。功能再多,别人接不进来就没用。

- [ ] **一键上手文档 / Getting Started**:5 分钟从安装到跑出第一条真实轨迹的教程(含 API key 配置、一个真实域的完整示例)。`@`
- [ ] **"接入你自己的环境" 手把手指南**(`docs/ADD_YOUR_ENV_zh.md`):写一个 `SandboxClientABC` 子类的完整模板 + 检查清单 + 常见坑。这是扩展性的核心卖点,必须有独立文档。`@`
- [ ] **配置化运行**:支持 YAML/JSON 配置文件描述一次完整 run(域、算子链、并发、模型),`python -m dataflow_agent run config.yaml` 即可,免写 Python。降低非开发同学的门槛。`@`
- [ ] **环境依赖收敛**:确认 `open-dataflow` 的重依赖(torch 等)对只用 API 的用户是否可选;给一个 `pip install dataflow-agent[minimal]` 的轻量安装路径。`@`
- [ ] **错误信息友好化**:常见错误(API key 缺失、网关不通、sandbox 未启动)给出明确的中文/英文提示和排查建议。`@`

## 2. 🔴 数据质量与可信度(框架的立身之本)

我们的差异化是"不只采集,还打分筛选修复"。这条线要做扎实、可量化。

- [ ] **数据质量报告**:一次 run 结束自动产出统计(成功率、平均步数、工具分布、质量分分布、过滤/修复情况),让用户对产出的数据有信心。`@`
- [ ] **可验证 reward 扩展**:coding 域已有 `run_tests`;为 text2sql(执行结果比对)、RAG(答案匹配)等域补"可验证/半可验证"的质量信号,减少对 LLM 裁判的依赖。`@`
- [ ] **去重升级**:`TrajectorySelector` 当前用动作签名 Jaccard;升级到**语义级去重**(embedding 距离),避免"换个说法的重复轨迹"。`@`
- [ ] **评估器成本优化**:支持 batch judging、缓存相同轨迹的评分,降低大规模打分成本。`@`

## 3. 🟡 更强的探索(算法升级)

- [ ] **价值引导的树搜索探索器**:在现有分支树基础上,引入"边探索边评估、把算力集中到高价值/高多样路径"的搜索策略(替代当前的盲采),提升单位算力的高质量轨迹产出。`@`
- [ ] **难度自适应预算**:先估种子难度,按难度动态分配探索预算(中等难度多探、不可解早停),提升数据效率。`@`
- [ ] **偏好数据导出**:从探索树的兄弟路径导出"好 vs 坏"的偏好对(DPO/过程奖励数据),一次 run 同时产 SFT + 偏好数据。`@`

## 4. 🟡 更多环境(覆盖面)

- [ ] **MCP 环境适配器**:一个 `MCPSandboxClient`,把任意 MCP server 的工具接进来——一步打通整个 MCP 生态,极大扩展可用环境。`@`
- [ ] **Text2SQL / RAG / 文档 域的开箱示例**:每个域一个可跑的 `run_<domain>.py` + 种子数据,让用户照葫芦画瓢。`@`
- [ ] **Shell / 通用工具 agent**:基于现有能力提供一个通用命令行 agent 环境示例。`@`
- [ ] 🟢 **多模态探索器**(长期):支持图像观察(GUI/VM 截图)。需要 LLM serving 加图像通道 + 探索循环区分图文观察,是框架级改造。`@`

## 5. 🟡 规模化与工程化(生产可用)

- [ ] **Refiner 之外的并发协调**:统一"算子并发 × LLM serving 并发"的配置,避免两层线程池相乘失控;给不同域(API vs coding)推荐默认并发。`@`
- [ ] **自适应限流**:遇到网关 429/超时自动降速、平稳后回升(AIMD),比固定并发更抗波动。`@`
- [ ] **多进程 / 多机分片**:`sharded_run` 目前单进程分片;扩展到多进程甚至多机并行,真正规模化打数据。`@`
- [ ] **进度与可观测性**:长跑时的进度条、实时统计、失败样本落盘,方便盯大批量任务。`@`

## 6. 🟢 协作与可持续(让"更多人"能共建)

- [ ] **CONTRIBUTING 指南**:代码规范、测试要求(新算子/新 sandbox 必须带测试)、PR 流程。`@`
- [ ] **CI**:PR 自动跑 46+ 离线测试(无需网络/GPU/key),保证不回退。`@`
- [ ] **算子/沙箱注册规范**:统一命名、`get_desc` 双语、参数文档约定,让新增组件风格一致。`@`
- [ ] **示例数据集与基准**:沉淀几个标准种子集 + 用它们产的样例数据,作为新用户的参照和回归基准。`@`
- [ ] **英文文档**:`DESIGN.md` / `CAPABILITIES.md` 英文版,面向更广受众。`@`

## 建议的推进顺序(给 owner 的话)

1. **先攻第 1 节(采纳门槛)+ 第 6 节的 CONTRIBUTING/CI**——没有这两块,再多功能也推广不动,也无法让别人放心贡献。
2. **再做第 2 节(质量报告 + 可验证 reward)**——这是我们相对"只会采集的沙箱"的核心差异,要让用户信得过产出的数据。
3. **第 4 节的 MCP 适配器**性价比很高——一个适配器换来整个 MCP 生态的环境。
4. **第 3 节探索算法升级**是研究性亮点,可与 paper 工作并行(相关探索算法调研见内部笔记,不在本仓库)。
5. **第 5 节规模化**在有真实大批量需求时再逐步补齐;`sharded_run` 已够起步。
